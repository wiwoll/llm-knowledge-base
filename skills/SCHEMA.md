# Wiki Frontmatter Schema

This document defines the canonical YAML frontmatter for all artefacts in the Redaktions-Wiki. Every skill that creates or modifies wiki content follows this schema. Optional fields should be omitted (not set to `null` or empty string) when not applicable.

> **Where this lives:** `skills/SCHEMA.md` in the tooling repo, installed alongside individual skills. Skills reference this document by reading `~/.claude/skills/SCHEMA.md` at runtime when they need the full schema.

---

## Core fields (all artefacts)

| Field | Type | Required | Notes |
|---|---|---|---|
| `lang` | ISO 639-1 (`de`, `en`, `fr`, `it`) | yes | One of `supported_langs` from kb-config. |
| `tags` | list of lowercase strings | yes | 3–8 tags. Medical tags use English MeSH-aligned terms when possible (`cardiology`, `oncology`, `glp-1-agonists`). |
| `created_at` | ISO 8601 UTC | yes | First write timestamp. |
| `updated_at` | ISO 8601 UTC | yes | Last meaningful edit. |

---

## Source artefacts (`raw/*` and `wiki/sources/*`)

In addition to the core fields:

| Field | Type | Required | Notes |
|---|---|---|---|
| `source` | string (URL or path) | yes | Original source URL/path. |
| `ingested_at` | ISO 8601 UTC | yes | When raw was added. |
| `type` | enum: `web`, `pdf`, `image`, `note` | yes | Format. |
| `status` | enum: `uncompiled`, `compiled` | yes | Compilation state (raw only). |

### Medical metadata (optional but encouraged for medical sources)

| Field | Type | Notes |
|---|---|---|
| `doi` | string | Digital Object Identifier, lowercased, no URL prefix. Example: `10.1056/nejmoa2034577`. |
| `pmid` | integer | PubMed identifier. Example: `33301246`. |
| `pmcid` | string | PubMed Central ID if available. Example: `PMC7745181`. |
| `journal` | string | Full journal name. Example: `New England Journal of Medicine`. |
| `journal_abbrev` | string | NLM abbreviation. Example: `N Engl J Med`. |
| `publication_date` | ISO 8601 date | Date of publication, not ingestion. |
| `authors` | list of strings | First-author-first list, max 6 names + `et al.` if more. |
| `study_type` | enum (see below) | Methodological category. |
| `evidence_level` | enum: `1a`, `1b`, `2a`, `2b`, `3a`, `3b`, `4`, `5` | Oxford CEBM levels. |
| `peer_reviewed` | boolean | True if published in peer-reviewed venue. |
| `funding_disclosed` | boolean | Whether funding sources are disclosed in the paper. |
| `coi_disclosed` | boolean | Whether conflicts of interest are disclosed. |
| `population` | string | Patient population (e.g., `adults with type 2 diabetes`). |
| `sample_size` | integer | n. |

### `study_type` enum

`rct` (randomized controlled trial), `meta-analysis`, `systematic-review`, `cohort` (prospective or retrospective), `case-control`, `cross-sectional`, `case-series`, `case-report`, `narrative-review`, `editorial`, `guideline`, `preprint`, `in-vitro`, `animal`, `other`.

## Concept artefacts (`wiki/concepts/*`)

In addition to the core fields:

| Field | Type | Required | Notes |
|---|---|---|---|
| `type` | enum: `concept`, `synthesis` | yes | `synthesis` = produced by `/kb-reflect`. |
| `editorial_status` | enum (see below) | yes | Fact-check / publication state. |
| `reviewed_by` | string | conditional | GitHub username, required when `editorial_status` ≥ `fact-checked`. |
| `reviewed_at` | ISO 8601 UTC | conditional | Required when `editorial_status` ≥ `fact-checked`. |
| `review_notes` | string | optional | Free-text reviewer notes. |
| `translation_of` | string (article slug) | optional | Slug of the canonical-language article this is a translation of. |
| `translations` | map (lang → slug) | optional | Set on the canonical article; lists language editions. |

### `editorial_status` enum

| Value | Meaning |
|---|---|
| `draft` | Auto-generated by LLM, not yet reviewed. **Default for any LLM-written concept article.** Do not cite externally. |
| `in-review` | Submitted for editor review; do not publish. |
| `fact-checked` | Reviewed by named editor; safe for internal use; ready for publication review. |
| `published` | Externally published or fully cleared for citation. Locked — further edits go via a new `draft` revision. |

LLM-managed skills only ever **set** `draft` for new content. Promotion through the workflow happens via `/kb-review`.

## Output artefacts (`outputs/*`)

In addition to the core fields:

| Field | Type | Required | Notes |
|---|---|---|---|
| `type` | enum: `qa-answer`, `lint-report`, `reflect-report`, `slides`, `chart` | yes | What was generated. |
| `question` | string | yes (qa-answer) | Verbatim question. |
| `answered_at` | ISO 8601 UTC | yes (qa-answer) | |
| `sources_consulted` | list of paths | yes (qa-answer) | Article paths read. |
| `generated_at` | ISO 8601 UTC | yes (reports) | |

## Citation format

When concept articles or Q&A answers cite a fact from a medical source, the inline citation uses:

```
[[sources/{slug}]]
```

For external publication, citations should be expanded to full bibliographic format including DOI/PMID — `/kb-output` does this automatically when rendering slides or articles for external use.

## Versioning

- Schema version: **1.0** (2026-04-30)
- Schema changes are backwards-compatible: skills tolerate missing optional fields and report them via `/kb-lint` rather than failing.
- Breaking schema changes require a `kb-migrate` skill (not yet implemented) and a new schema version line.
